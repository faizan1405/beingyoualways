# server/ rules
- `MEDIA_ROOT` is resolved to an absolute path once in `config.ts`; production refuses a folder inside the deploy directory and checks it is writable at start — GitHub redeploys replace the app folder.
- Google sign-in reads `AUTH_GOOGLE_ID`/`AUTH_GOOGLE_SECRET`/`GOOGLE_REDIRECT_URL`, and `AUTH_SECRET` signs the flow cookie — names the owner configures on Hostinger.
- WhatsApp: only the server calls Meta (`whatsappGraph.ts`); every outbound message is a `WhatsAppMessage` row sent by the leased worker, and webhooks are stored before processing — restarts and retries never lose or double-send.
- Consent purposes: campaigns use only `marketing`; the bag-page reminder has its own `cart_reminder` purpose and a cart send needs the newest of the two to be a yes; any `marketing` opt-out also records a `cart_reminder` opt-out — a reminder choice must never enrol anyone in offers.
- `STORE_ENVIRONMENT` (staging|production) is required in production and stamps the database + `MEDIA_ROOT` at first start (`environmentMarker.ts`); staging forces test orders and Razorpay test keys, its own host-only cookies, and sends WhatsApp/SMTP only to the allow-listed testers — so a test copy can never touch live data or real customers.
- `npm run deploy:check` (`services/preflight.ts`) is the deploy gate: read-only, never prints secrets; add a check there for every new required setting or provider.
